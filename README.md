# 安大电费查询（astrbot_plugin_ahu_elec）

安徽大学宿舍电费查询的 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 插件。通过安徽大学一卡通系统（`ycard.ahu.edu.cn`）的「电控缴费」接口，查询绑定宿舍的**照明电费**与**空调电费**剩余电量。

- 纯 Python 实现：`httpx` 异步请求 + 内置纯 Python 3DES，**不需要浏览器、不需要 Node.js**
- 配置页下拉选择缴费窗口（**电控缴费 A / B / C**），不用记接口 id
- 支持**定时推送**（cron），到点自动把电费发到指定 QQ 群 / 私聊
- 支持**会话白名单**，只允许指定群聊或私聊使用
- 换宿舍不用改插件：宿舍由学校接口按当前账号实时返回，在手机端重新绑定即可

作者：秉烛 ｜ 协议：MIT

## 一、使用前提（请先确认，否则会查不到）

1. **网络能访问学校服务**
   插件所在机器必须能访问 `one.ahu.edu.cn` 与 `ycard.ahu.edu.cn`。
   实测**校外网络直连会连接超时**，因此需要：
   - 机器在**校内网**（校园 Wi-Fi / 宿舍网 / 实验室网）中，或
   - 机器已连接**安徽大学校园 VPN**（校外访问校内资源用）
   判断方法：在插件所在机器上打开 `https://ycard.ahu.edu.cn/charge-app/`，能打开即可。

2. **已有可用的统一身份认证账号**
   通常是学号 + 统一身份认证密码（与 `one.ahu.edu.cn` 网页登录一致）。

3. **已在手机端绑定宿舍**
   打开 `ycard.ahu.edu.cn` → 进入对应的**电控缴费窗口**（A / B / C）→ 绑定你的校区、楼栋、楼层、房间。
   **三个窗口的绑定相互独立**：插件里选哪个窗口，就查哪个窗口下绑定的房间。没有绑定会提示「没有绑定房间」。

4. **AstrBot 版本**
   已在 **AstrBot v4.29.4** 上验证。低于 v4.28 的版本可能因指令过滤机制不同出现 `/电费` 不触发（本插件已通过指令别名兼容新旧两种唤醒方式）。

5. **Python 依赖**
   `httpx`、`APScheduler`（AstrBot 后端一般已自带，缺失时见「安装」一节）。

## 二、三个缴费窗口说明

安徽大学一卡通系统里共有三个电控缴费窗口，对应接口项目 id：

| 配置页选项 | 项目名称 | feeitemid |
|---|---|---|
| `A` | 电控缴费A | 408 |
| `B` | 电控缴费B | 428 |
| `C`（默认） | 电控缴费C | 488 |

补充说明：

- 「电控缴费C」在系统里还有两个同名项目（429、468），通常用于不同校区/楼栋。默认用 488；**若 C 窗口提示没有绑定房间，可把高级项 `feeitemid` 依次改成 `429`、`468` 再试**。
- 查询逻辑是通用的：读取当前窗口绑定的房间，若房间名含「空调」就自动补查同楼同层的「照明」房间，反之亦然。只绑了一路也能正常显示；另一路找不到时只显示已绑定的那一路。
- 所以 A/B/C 选哪个都行，**取决于你在手机端把宿舍绑在了哪个窗口**。

## 三、安装

### 方式一：直接放入插件目录（推荐）

1. 下载本仓库（或 Release 里的 zip）。
2. 把整个 `astrbot_plugin_ahu_elec` 文件夹放到 AstrBot 的插件目录：
   ```
   AstrBot/data/plugins/ahu_elec/
   ```
   > AstrBot 默认数据目录见其文档；Docker 部署通常是 `data/plugins/`。
3. 若目录内缺少依赖，在后端 Python 环境执行：
   ```bash
   pip install httpx APScheduler
   ```
4. 重启 AstrBot，或在 WebUI「插件管理」里重载插件。

### 方式二：WebUI 上传 zip

AstrBot 管理面板 → 插件管理 → 安装插件 → 上传本项目的 zip 包，然后重载。

### 方式三：Git 克隆

```bash
cd AstrBot/data/plugins
git clone <本仓库地址> ahu_elec
```

安装后在「插件管理」中应看到「安大电费查询」已加载。

## 四、配置（管理面板 → 插件 → 安大电费查询）

| 配置项 | 类型 | 说明 |
|---|---|---|
| `username` | 文本 | 学号 / 一卡通账号 |
| `password` | 文本（隐藏） | 统一身份认证密码。仅保存在本机 AstrBot 配置文件中，不会上传，也不要分享配置文件 |
| `fee_window` | 下拉 A/B/C | **缴费窗口**，默认 C。选你在手机端绑定宿舍的那个窗口 |
| `feeitemid` | 文本，可留空 | 高级项。留空按窗口自动映射（A=408 / B=428 / C=488）；C 查不到绑定时可试 429、468 |
| `schedule_enable` | 开关 | 是否启用定时推送 |
| `schedule_cron` | 文本 | 定时表达式，5 段 cron：`分 时 日 月 周` |
| `schedule_target` | 文本，可留空 | 推送目标会话（UMO）。**建议留空**，在目标群/私聊里发 `/电费bind` 自动填入 |
| `whitelist_enable` | 开关 | 是否启用会话白名单 |
| `whitelist_groups` | 列表 | 允许使用的 QQ 群号，如 `["123456789"]` |
| `whitelist_private` | 列表 | 允许使用的 QQ 号（私聊），如 `["10001"]` |

### 定时表达式示例

| 表达式 | 含义 |
|---|---|
| `0 9 * * *` | 每天 09:00 |
| `0 12,18 * * *` | 每天 12:00 和 18:00 |
| `30 8 * * 1-5` | 工作日 08:30 |
| `0 10 1 * *` | 每月 1 日 10:00 |

> 修改 `schedule_*` 后需**重载插件**才会重新注册定时任务（插件加载时按配置注册）。

## 六、定时推送怎么用

1. 在配置页打开 `schedule_enable`，填好 `schedule_cron`（如 `0 9 * * *`）。
2. **不要手填 `schedule_target`**，改为：把机器人拉进目标 QQ 群（或直接私聊机器人），在群里 / 私聊里发送：
   ```
   /电费bind
   ```
   插件会把当前会话地址写进配置并回复确认。
3. 重载插件，定时任务生效。到点会自动推送一条和 `/电费` 相同的电费信息。

说明：

- 定时推送**不受会话白名单限制**（白名单只拦手动指令），避免自己把自己拦掉。
- 若手动填 `schedule_target`，格式为 `平台ID:消息类型:会话ID`，例如 `robot01:GroupMessage:123456789`。**第一段是适配器 ID，不一定等于适配器类型名**（如 aiocqhttp 适配器的 id 可能是 `robot01`）。可用 `/sid` 查看当前会话的 UMO 并原样复制。
- 插件已内置 UMO 容错：若第一段写成了适配器类型名（如 `aiocqhttp`）导致发不出，会自动遍历已加载平台，替换成真实平台 id 重发。

## 七、会话白名单

启用 `whitelist_enable` 后：

- 只有 `whitelist_groups` 里的群、`whitelist_private` 里的 QQ 号可以使用四个指令；
- 其他会话一律回复「无权限，如有需要请联系管理员」；
- `/电费bind` 同样受白名单保护，防止陌生会话篡改推送目标；
- 定时推送不受影响。

## 八、常见问题（FAQ）

**Q1：提示「无法连接学校服务器（网络超时/不通）」**
插件所在机器访问不了 `one.ahu.edu.cn`。多为校外网络直连导致，请连校园网或校园 VPN；也可先用浏览器打开 `https://ycard.ahu.edu.cn/charge-app/` 验证。

**Q2：提示「该账号在 电控缴费X 下没有绑定房间」**
该窗口下没有绑定宿舍。去 `ycard.ahu.edu.cn` 手机端进入对应窗口绑定；或换 `fee_window` 选另一个窗口；C 窗口还可试 `feeitemid=429` / `468`。

**Q3：只显示了一路电量（只有空调或只有照明）**
说明该窗口只绑定了其中一路，且同楼同层没有找到另一路的同名房间。这不影响已绑定那一路的查询结果。

**Q4：`/电费` 没反应，消息被当成普通聊天交给 AI**
新版 AstrBot 的唤醒前缀可能为空数组，`/电费` 原文匹配不上指令名。本插件已为四个指令注册带 `/` 的别名，若仍不触发：
- 确认插件已加载、无报错；
- 尝试直接发 `电费`（不带斜杠）；
- 确认 AstrBot 版本 ≥ v4.28。

**Q5：定时推送没发出来**
- `/电费status` 看是否启用、目标是否为空、下次运行时间；
- 目标会话是否还在（机器人是否被踢出群）；
- 日志里是否有 `cannot find platform for session ...`：说明 `schedule_target` 第一段写错，重新 `/电费bind` 即可；
- 修改配置后是否重载了插件。

**Q6：查询时间和电量对不上 / 数字偶尔变化**
接口在每日日结时段（约 23:30–00:30）可能返回旧值或空值，稍后再查即可。

**Q7：换宿舍了要改配置吗？**
不用。宿舍是学校接口按当前账号实时返回的，在手机端 ycard 重新绑定即可，插件配置里没有任何宿舍信息。

**Q8：日志出现 `Conflicting modules: bcrypt` 之类的依赖预加载告警**
这是 AstrBot 新版本依赖预加载的通用告警（其他插件也会出现），不影响本插件加载与查询。

**Q9：密码安全吗？**
密码只用于 CAS 登录换取 token，保存在本机 AstrBot 的插件配置文件中（`data/config/ahu_elec_config.json`），不会发往任何第三方。请勿把该配置文件或本插件的配置截图公开。token 在内存中缓存约 1.5 小时。

## 九、隐私与免责

- 本插件为个人开发的非官方工具，与安徽大学官方无关。
- 插件不收集、不上传任何账号、密码、宿舍信息；所有请求只发往 `one.ahu.edu.cn` 与 `ycard.ahu.edu.cn`。
- 请合理设置查询/推送频率，避免对学校系统造成压力。
- 接口若变更（项目 id、字段结构变化）可能导致查询失败，欢迎提 Issue。

## 十、实现说明（给二次开发者）

```
ahu_elec/
├── main.py            插件入口：指令、配置、定时调度、白名单、结果格式化
├── ahu_elec.py        CAS 登录、token 获取、绑定查询、电量查询
├── synjones_des.py    纯 Python 3DES（登录参数加密）
├── _conf_schema.json  AstrBot 配置页定义
├── metadata.yaml      插件元信息
├── requirements.txt   依赖
├── LICENSE            MIT
└── README.md
```

查询链路：

1. `GET https://one.ahu.edu.cn/cas/login?service=...` 取 `lt` / `execution`
2. `POST /cas/device` → `POST /cas/login`（表单，账号密码 3DES 加密）→ 拿 `ticket`
3. `GET SERVICE?ticket=` → `POST https://ycard.ahu.edu.cn/berserker-auth/oauth/token` 取 `access_token`
4. `GET /charge/sceneBind/getList?feeitemid=<id>` 取当前账号在该窗口绑定的 `sceneinfo`
5. `POST /charge/feeitem/getThirdData`（`type=IEC, level=4`）查房间剩余电量
6. 若绑定房间名含「空调」/「照明」，用 `type=select` 接口在对应楼栋、楼层找同名房间，补查另一路

三个窗口的 id 可通过 `GET /charge/feeitem/showFeeitem` 或 `/charge/feeitem`（需登录）获取完整缴费项目列表。

欢迎 PR：新增校区/楼栋适配、结果模板、企业微信/Telegram 推送等。
